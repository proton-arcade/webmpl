Mixt Site Converter

Turn a website from out there into a website for this project.

1. Give it a page

Paste the HTML of the page you want. Nothing is fetched: this page has no network access and makes no requests, so what you paste is the only thing it works from.

2. What it did

Remote assets pointed inside

Each of these was an absolute address on somebody else's machine. It now points at a file under ./vendor/. Nothing was downloaded — put the file there yourself, or the page does without it.

What the converter changes, and why

    
    
      
  1. Absolute addresses become local ones. https://cdn.example/style.css
          becomes vendor/cdn.example-style.css. A page that pointed at a CDN now points
          at a file in its own folder, and nothing on it reaches another machine.
    2. 
      
  2. Protocol-relative addresses are absolute in disguise. //cdn.example/x
          gets the same treatment; left alone it would still try to leave.
    3. 
      
  3. Integrity hashes are dropped. The hash describes the remote file. Keeping it while
          serving a local copy would make the browser refuse to run anything.
    4. 
      
  4. Things that need a foreign machine are commented out — iframes, forms that post
          away, prefetch and preconnect hints, beacons, service worker registration — each with a
          note saying what it was and why it went.
    5. 
      
  5. A manifest is produced listing every change, so the result can be checked instead
          of taken on trust.
    6. 
      
  6. A website.ini is produced in the [Website] key-per-line
          form the rest of this project uses.
    7.

      dependencies and no build step: open converter/index.html and it runs, over http
      or straight off the disk.
